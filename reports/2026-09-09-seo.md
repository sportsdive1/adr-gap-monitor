상태: 사용자 승인 범위 구현·Git 반영·Cloudflare 배포·운영 검증 완료. Search Console의 검색어/페이지별 내역은 별도 계정 확인이 남아 있음.

## 개선 전 기준과 해석

사용자가 최근 28일 수치로 알려 준 기준이다. 계정 보고서 자체를 직접 열어 검증한 수치는 아니다.

| 지표 | 기준 |
|---|---:|
| GA4 사용자 | 43명 |
| GA4 특정 하루 사용자 | 16명 |
| Search Console 클릭 | 5회 |
| Search Console 노출 | 14회 |
| Search Console 평균 게재순위 | 3.8 |
| 클릭률(5 ÷ 14 × 100) | 약 35.7% |

현재 관찰에서는 검색결과 클릭률보다 절대 노출 수가 부족한 점이 두드러진다. 다만 14회는 작은 표본이므로 평균 순위 3.8을 전체 주요 검색어의 순위로 일반화할 수 없다. 브랜드 검색·직접 확인 검색이 섞였는지, 홈/가이드 중 어느 페이지에 노출됐는지는 아직 모른다. GA4 사용자 수와 Search Console 클릭 수는 같은 지표가 아니므로 43명에서 5회를 빼서 다른 유입 사용자를 계산하지 않는다.

앞선 공개 점검에서 홈·가이드 200 응답, robots·canonical·기본 메타를 확인했다. 두 페이지의 GA4 page_view 요청 생성도 확인했지만, GA4 최종 수집·내부 트래픽 필터는 확인하지 않았다. HTTP가 HTTPS로 이동하지 않고 /index.html·가이드 끝 슬래시 없는 주소도 200으로 제공되는 점을 발견했다. www는 DNS 조회가 실패했다. 공개 검색 결과만으로 미색인을 단정하지 않았다.

초기 HTML 생성은 Worker 실행 인스턴스 초기화 때 한 번 수행하며 Yahoo를 호출하지 않는다. 실제 가격과 시각을 HTML에 미리 넣거나 최신으로 꾸미지 않는다. 같은 HTML을 일반 사용자와 검색봇에게 제공한다. 기존 CSS·화면 배치·시장 시각 표시·데이터 공급처·시세 선택·캐시·자동 갱신 주기는 바꾸지 않았다. 새로운 프레임워크·DB·공급처·기업별 랜딩 페이지를 추가하지 않았다.

홈의 app.js 참조에 `?v=20260909-seo`를 붙여 새 HTML이 이전 캐시의 클라이언트 코드를 사용하는 위험을 줄였다. HTML 파일 직접 열기는 지원하지 않으며 기존처럼 Worker 주소로 미리본다. JavaScript 비활성화 안내만 해당 환경에서 보이고 작동하지 않는 버튼은 비활성화한다.

가이드 예시는 국내 130,000원·ADR 비율 0.5·환율 1,300원/USD·ADR 55달러를 가정한다. 국내 환산가 50달러, ADR 괴리율 10.00% 높음, ADR 원화 환산가 143,000원 및 국내 기준 9.09% 낮음은 실제 계산 모듈과 대조했다. 예시를 실제 종목·시세나 수익 기회로 표현하지 않았다. ADR 개념은 [SEC Investor.gov 안내](https://www.investor.gov/introduction-investing/investing-basics/glossary/american-depositary-receipts-adrs)를 연결했다.

## 배포 확인과 남은 계정 작업

1. 커밋 `1364c5e2fe9ed9cab03ffae5c5f0cfa4f7acb101`의 GitHub Actions verify(run `34247819430`)가 성공했다. Custom Domain 설정 커밋 `71df3727dec84f25a5eeff805878e49edfc92db`도 GitHub Actions verify(run `34248685993`)가 성공했다.
2. Cloudflare 자동 배포 최신 버전은 `b50c740c-fa3b-4269-8b40-f81fd0167231`(2026-09-08 16:04 UTC)이며 운영 트래픽에 적용됐다. 로컬 Wrangler 중복 배포는 하지 않았다.
3. 운영의 홈·가이드·HTTP/별칭 308·쿼리 보존, 초기 `/api/market?company=sk-hynix`+`/api/market` 2회, 수동 `/api/market?force=1` 1회, 환율·한국/ADR 기준 시각, 9개 기업, 오류 없음, 데스크톱/모바일 가로 넘침 없음을 확인했다.
4. `adrgap.com`은 Cloudflare Custom Domain으로 유지되고, `www.adrgap.com`도 Custom Domain 선언 후 Cloudflare AAAA가 생성됐다. `https://www.adrgap.com/`와 HTTP가 `https://adrgap.com/`로 308 리디렉션된다. 별도 CNAME을 추가하지 않았다.
5. Search Console에서 홈과 가이드의 URL 검사로 색인 가능 여부와 Google 선택 표준 URL을 확인한다. 필요할 때 색인 생성 요청을 한 번 수행하되 제출 완료와 색인 완료를 구분한다.
6. 최근 28일 검색어·페이지 탭에서 브랜드/비브랜드 및 홈/가이드 노출을 분리하고 2~4주 후 같은 조건으로 비교한다. GA4에서 16명이 발생한 날짜의 세션 소스/매체·랜딩 페이지와 내부/테스트 방문 가능성도 확인한다.

계정 브라우저 도구가 실행 오류로 동작해 Search Console 검색어·페이지별 내역과 URL 색인을 직접 확인하지 못했다. Cloudflare는 Wrangler OAuth 인증 후 Custom Domain 설정과 DNS/HTTPS 응답을 확인했다. 사용자 제공 요약 수치는 기준에 반영했지만 세부 검색 조회까지 완료한 것으로 보고하지 않는다. SEO 기술 보완은 노출·방문자 증가를 보장하지 않으며, 현재 근거만으로 저조한 유입의 단일 원인을 확정할 수 없다.
